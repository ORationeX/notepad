# UI설계서 작성 규칙

이 문서는 다음 5개 산출물을 기반으로 도출한 **UI설계서 PPTX 작성 표준(구성 · 레이아웃 · 디자인 · 표/도형/텍스트/코드 규격)**이다.

1. `UI설계서_물류창고관리 구축_1차_20260714.pptx` (1차 초안: 11장 — 와이어프레임 · Mermaid/정책표 · Object · DB)
2. `UI설계서_물류창고관리 구축_1차_20260721.pptx` (1차 보완: 12장 — 정책표/도형 플로우차트 분리 · Object 분할)
3. `UI설계서_물류창고관리 고도화&운영_20261102.pptx` (고도화 초안: 20장 — ESL 신규 와이어프레임 + 1차 이관)
4. `UI설계서_물류창고관리 고도화&운영_V0.11_20261111.pptx` (고도화 통합본: 54장 — 화면 목록 · 실제 캡처 주석 · Event Design 도입)
5. `UI설계서_물류창고관리 고도화&운영_V0.1_20261112.pptx` (고도화 최신 완결본: 82장 — Query Design · SQL 하이라이트 · 공통 쿼리/혼용 규칙 완비)

**완전 빈 `.pptx`에서 시작하더라도 이 문서만 보고 동일한 디자인과 구조로 생성할 수 있도록** 모든 슬라이드 규격, 마스터 요소, 절대 좌표(`cm` / `EMU`), 색상(`#RRGGBB`), 그라데이션, 테두리, 글꼴, 자간/줄간격, 섹션별 구성 규칙을 정의한다.

> **표준 적용 원칙**: 최신 완결본(`V0.1_20261112`)을 기본 표준으로 삼는다. 다만 `V0.1`에 포함되지 않은 **Flow Chart**는 `구축_1차_20260721` / `고도화&운영_20261102` 규격을, **순수 도형 와이어프레임**은 `구축_1차_20260714` / `고도화&운영_20261102` / `V0.1 S13` 규격을 정본으로 통합 정의한다.

## 1. 파일 명명 및 문서 전체 구성

### 1.1 파일명 규칙

```text
UI설계서_{시스템명} {구분}_{버전}_{YYYYMMDD}.pptx
```

- `{시스템명}`: 대상 시스템명 (예: `물류창고관리`)
- `{구분}`: 프로젝트 단계 또는 성격 (예: `구축_1차`, `고도화&운영`)
- `{버전}`: 선택적 버전 표기 (`V0.1`, `V0.11` 등). 생략 시 날짜만 표기.
- `{YYYYMMDD}`: 문서 기준일.

### 1.2 전체 슬라이드 구성 및 순서

문서는 **표지 → (선행/별도 모듈) → 화면 개발 목록 → 화면별 설계 묶음 → 공통 기능 설계** 순서로 배치한다.

```text
1. 표지 (1장)                                  [레이아웃: 표지]
2. (선택) 별도 담당·선행 모듈 묶음               [레이아웃: 마스터]
3. 화면 개발 목록 (1장, 섹션: 화면 목록)         [레이아웃: 마스터]
4. 화면별 상세 설계 묶음 (화면 목록 순서대로 반복) [레이아웃: 마스터]
   ├── 4-1. UI Design (PC 화면)                 *필수
   ├── 4-2. (선택) UI Design (PDA 화면)         *PDA 동시 변경 시
   ├── 4-3. (선택) Flow Chart (정책표 / 흐름도)  *복잡한 인터락·분기 로직 시
   ├── 4-4. Object Design                       *신규·수정 항목/그리드/전달값 정의 (다중 슬라이드 가능)
   ├── 4-5. Event Design                        *이벤트/API/Validation이 있을 때
   ├── 4-6. (선택) DB                           *테이블 신규 생성·컬럼 변경 시
   └── 4-7. Query Design                        *신규·수정·참조 SQL 존재 시 (다중 슬라이드 가능)
5. 공통 기능 설계 (다수 화면 공통)               [레이아웃: 마스터]
   ├── 5-1. Event Design — 공통 처리 매트릭스 (예: 리워크 혼용 박스 처리 (공통))
   └── 5-2. Query Design — 공통 쿼리 모음 (다중 슬라이드 가능)
```

## 3. 공통 슬라이드 헤더 및 메타데이터 규칙

표지(`Slide 1`)를 제외한 **모든 본문 슬라이드(`y = 0 ~ 4.0 cm`)**는 아래 4개 요소로 헤더를 구성한다.

### 3.1 상단 헤더 3요소 (`y = 0.0 ~ 2.256 cm`)

| 요소 | 도형 | 위치 (`x, y`) | 크기 (`w × h`) | 글꼴 · 정렬 · 색상 | 비고 |
| --- | --- | --- | --- | --- | --- |
| **① 화면 제목 (`Rect 0`)** | `rect` (`noFill`, `noLine`) | `x=1.189cm`, `y=0.889cm` | 기본 `w=14.360cm` / 긴 제목 `16.695cm` / 최장 `17.222cm`, `h=1.367cm` | `맑은 고딕 30pt Bold #404040`, `algn='l'`, `anchor='t'`, 여백 `0` | 부제 병기 시 `(부제1 \| 부제2)` 부분만 **`8pt Bold #404040`** |
| **② 섹션 라벨 (`Rectangle 2`)** | `rect` (`noFill`, `noLine`) | `x=18.559cm`, **`y=0.981cm`** (`UI Design`, `화면 목록`) 또는 **`y=0.724cm`** (그 외 섹션) | `w=8.601cm`, `h=1.058cm` | `맑은 고딕 20pt Regular #8D9682`, `algn='r'`, `anchor='ctr'`, 여백 `l/r=0.254cm, t/b=0.127cm` | 표기 목록: `UI Design`, `화면 목록`, `Flow Chart`, `Object Design `, `Event Design `, `DB`, `Query Design ` |
| **③ 개발 구분 배지 (`Rect 0`)** | `rect` (`noFill`, `noLine`) | `x=20.661cm`, `y=0.0cm` | `w=6.856cm`, `h=1.039cm` | `맑은 고딕 20pt Bold #77933C`, `algn='l'`, `anchor='t'`, 여백 `0` | **`UI Design` 슬라이드에만** 표시. 3종 고정: `(신규기능 신규 개발)`, `(기존기능 수정 개발)`, `(데이터 추가)` |

> **왜 `y` 좌표가 두 가지인가?** `UI Design` 슬라이드는 `y=0.0cm` 자리에 `(신규기능 신규 개발)` 등 개발 구분 배지가 들어가므로 `UI Design` 라벨이 `y=0.981cm`로 내려온다. 배지가 없는 `Flow Chart`, `Object Design`, `Event Design`, `DB`, `Query Design`은 `y=0.724cm`에 위치한다. `화면 목록`은 배지가 없으나 `y=0.981cm`를 사용한다.

### 3.2 화면 메타데이터 2×4 표 (`Group 33`)

`화면 목록` 슬라이드를 제외한 모든 본문 슬라이드 상단 구분선(`y=2.352cm`) 바로 아래에 배치한다.

#### 5.8.3 참조 쿼리 표 (`N×5`) 및 다중 블록 간격
해당 화면이 함께 호출하지만 수정하지 않는 공통/기존 쿼리나 대체 삭제된 쿼리를 페이지 하단(`Query` 박스 아래 **`+0.305cm`** 간격)에 정리한다. 한 슬라이드에 여러 `Query ID` 블록을 수직 배치할 때도 이전 `Query` 박스와 다음 `Query ID` 메타데이터 표 사이 간격을 동일하게 **`+0.305cm`**(`~0.30cm`)로 유지한다.

- **위치/크기**: `x=0.463cm, w=26.591cm`, `cols=[2.639, 7.361, 6.389, 6.528, 3.674] cm`, 행 높이 각 `0.458cm`.
- **Row 0**: `" 참조 쿼리 (공통 사용 · 삭제 · 변경 없음)"` (`8.0pt Bold`).
- **Row 1**: `구분` | `Query ID` | `XML 파일` | `연결 이벤트` | `비고` (`7.5pt Bold`, 가운데).
- **Row 2+**: `7.0pt`, `구분` 열만 `Bold` 가운데 정렬, 나머지 4열은 `Regular #000000` 좌측 정렬:
  - `공통 사용`: **`#548235 Bold`** (녹색, 공통 쿼리 슬라이드 번호 안내 예: `공통 쿼리 47 ~ 51장`)
  - `변경 없음`: **`#7F7F7F Bold`** (회색, 예: `SELECT * (새 컬럼 자동 포함)`)
  - `삭제`: **`#C00000 Bold`** (빨강, 대체된 공통 쿼리명 안내)

## 6. 빈 PPTX에서 처음부터 생성할 때의 구현 규칙

빈 `Presentation()`에서 스크립트(`python-pptx`) 또는 PowerPoint로 동일 디자인을 생성할 때 아래 순서와 규칙을 준수한다.

1. **캔버스·마스터 우선 생성**: 슬라이드 크기를 `9906000 × 6858000 EMU`로 고정하고, 기본 레이아웃에 의존하지 말고 `마스터` 레이아웃에 상/하단 그라데이션 구분선(`y=2.352cm`, `18.009cm`), 중앙 페이지 번호(`y=18.283cm`, ` - <slidenum> / {N} -`), 우하단 로고(`x=24.619cm, y=18.281cm`)를 먼저 배치한다.
2. **테이블 기본 스타일 제거**: `python-pptx`의 `add_table()`은 기본 파랑 테마 스타일(`tableStyleId`)을 자동 삽입하므로, 표 생성 직후 `<a:tblPr>` 내부의 `tableStyleId` 및 `firstRow`/`bandRow` 속성을 제거한 뒤 4절의 그라데이션 채우기, 외곽선(`1.5pt #384469`), 내부 격자선(`0.5pt #000000`)을 셀 단위로 직접 지정한다.
3. **선형 그라데이션 각도**: 표 헤더와 `Group 33` 라벨의 오렌지 그라데이션은 반드시 `ang="5400000"`(90°, 위→아래) 수직 그라데이션(`#FFD557 → #FFE38E → #FFF0C3`)을 적용한다.
4. **우측 설명 패널 번호 매기기**: `1) 2) 3)` 항목은 문자열에 `"1) "`을 하드코딩하지 않고 문단 `<a:pPr>`에 `marL="228600" indent="-228600"`과 `<a:buAutoNum type="arabicParenBoth" startAt="1"/>`을 부여하여 줄바꿈 시에도 내어쓰기가 유지되게 한다.
5. **콘텐츠 하단 한계선 준수**: 모든 본문 콘텐츠(표, 캡처, SQL 박스, 주석)는 하단 구분선(`y=18.009cm`) 위인 **`y ≤ 17.85cm`** 이내에 끝나야 한다. 이를 넘기면 새 슬라이드로 분할한다.
